# Recovery plan — Disquiet

**Status:** In progress — Step 1 done and verified 2026-10-17. Step 2 next.

This plan replaces Phases 5 and 6 of `docs/plans/2026-09-13-mvp.md`. It records the audit of
2026-10-16 and the steps to get the project back on track. Follow the steps in order. Do not
start a step before the step above it is done and verified.

## Roles

- **The user** is the final authority on every decision, on this plan, and on the results.
- **Claude Code** is the default agent for this repository. It writes code and docs, and it
  asks the user before any decision with a real tradeoff.
- Only the user approves a commit (see `docs/CONTEXT.md`, "User instruction").

## 1. Audit findings (2026-10-16)

### What matches the plan

- The content layer (`src/content.config.ts`, `src/lib/content/index.ts`) matches ADR-0002 and
  ADR-0003.
- The contact function (`api/contact.ts`) matches ADR-0004. Its 20 unit tests pass.
- The contact form logic (`src/components/contact/reducer.ts`, `createContactForm.ts`) is
  clean and tested.
- The stack (Astro static output, Bun, Vercel, strict TypeScript) is in place.

### What moved away from the plan, most severe first

1. **The contact form is broken on the `add-cases` branch.** Commit `b7331090` (2026-10-12)
   removed the form script, the honeypot field, the error elements, and the `mailto`/`<noscript>`
   fallback. A plain HTML POST gets a 415 response from the function. `main` and the production
   deploy (2026-10-11) are older than this commit, so production is not affected.
   A second, older bug: `performance.now()` returns fractions in Chrome, but the schema wants an
   integer `elapsedMs`. The check in the browser then failed with no visible message. Firefox
   rounds the timer, so a Firefox test can pass.
2. **The CSP blocks the fonts.** `vercel.json` allows styles and fonts from `'self'` only, but
   `BaseLayout.astro` loads 12 font families from Google Fonts. The plan specified 3
   self-hosted fonts, 120 KB maximum in total.
3. **`vercel.json` mixes `routes` with `headers`.** Vercel documents `routes` as legacy and
   says not to combine it with `headers`. Correction (2026-10-16): `vercel ls` shows that all
   deploys succeed, so this is not a build failure. Step 2 still replaces `routes`.
4. **The design tokens do not reach the page.** Tailwind v4 ignores `tailwind.config.js`. The
   build output has no `bg-bg`, `text-text`, or `font-heading` classes. `semantic.css` has
   self-references (for example `--radius-sm: var(--radius-sm)`).
5. **The theme is forced to light mode in 3 places.** The plan specified light, dark, and
   system modes. There are 4 copies of the toggle code. The toggle stops after a
   `ClientRouter` page change.
6. **Page content defects.**
   - `og:title` renders as the literal text `{title}`. `og:url` is `https://example.com/`.
   - `src/content/work/example-project.mdx` never loads. It does not match `**/index.mdx`.
   - `Header.astro` ignores the `NAV` model and links to `/writing`, which returns 404.
   - Pages put a `<main>` element inside the `<main>` element of the layout.
7. **The experience feature (ADR-0008) does not run.**
   - `Landing` goes into a slot that does not exist, so it never shows.
   - `Exit.astro` uses an `is:inline` script with `@/` imports. A browser cannot resolve them.
   - `DetourSketch` uses `p.random()` without the seed.
   - p5 is 1 MB after minification. ADR-0008 says 5 KB.
   - `api/seed.ts` hashes the IP address and sets a cookie for 1 year. This conflicts with
     ADR-0007 and with `CONTEXT.md` §5. The privacy page does not mention it.
   - The seed stays in `localStorage` permanently, so a later visit is not new.
8. **The quality gates exist only in the docs.**
   - CI does not run lint, typecheck, tests, build, size budgets, axe, or Lighthouse.
   - The CI `secret-guard` job fails on `SITE_URL` in `src/config/site.ts`.
   - The CI `lint-docs` job calls `bun ts-node`, which is not installed.
   - `src/config/site.test.ts` fails. It expects the name `Disquiet`.
   - `docs/PI_CONTEXT.md` reports work as complete that is not complete.
9. **The Vercel project uses the framework preset "Other".** Its output directory is
   `public`, not `dist`, so a deploy probably serves only the files in `public/`. Production
   deploys took 1–2 seconds, which supports this. `vercel dev` also failed: it tried to run
   `yarn`. Fixed on 2026-10-16 in `vercel.json` (`framework`, `installCommand`,
   `buildCommand`, `outputDirectory`, `devCommand`). Not yet confirmed on a deploy.
10. **Unrelated or dead files.** `Dockerfile` and `pi.yaml` configure a different coding agent.
    Astro does not read `vite.config.ts`, so `sonda` has no effect.

**Root cause:** More than one tool changed the repository, and no working CI checked the
result. The status docs then reported work as done before anyone verified it.

## 2. Decisions kept

Astro static output, Bun, Vercel, the content layer, the contact function, and its tests stay.
Only the UI and style layer gets a rebuild.

## 3. Steps

Each step ends with a verification. A step is done only when its verification passes.

### Step 1 — Restore the contact form

1. Restore the form markup, the honeypot, the error elements, the fallbacks, and the script
   from commit `92b734aa` into `src/pages/contact/index.astro`.
2. Remove the nested `<main>` element on that page.
3. Verify: `bun run build` passes, and the built page loads the form script from a file (the
   CSP blocks inline scripts).
4. Verify with the user: run the form against `vercel dev` or a preview deploy, and run items
   6 and 7 of the smoke test in `docs/RUNBOOK.md`.

### Step 2 — Fix the platform settings

0. Confirm on a preview deploy that the `vercel.json` framework settings work and that the
   deploy serves the Astro pages.

1. Replace `routes` in `vercel.json` with a configuration that Vercel accepts together with
   `headers`.
2. Self-host 2 or 3 fonts. **DECISION NEEDED (user):** which fonts.
3. Remove Google Fonts. Make the CSP match what the site loads.
4. Add GoatCounter (ADR-0006), or record a decision to defer it.
5. Verify on a preview deploy: headers present, fonts load, no CSP errors in the console.

### Step 3 — Make CI the only gate

1. Rewrite `.github/workflows/ci.yml`: install, lint, format check, typecheck, depcruise,
   test, build, bundle-size check, axe, Lighthouse CI.
2. Fix the `secret-guard` job so it searches for secret values, not variable names.
3. Fix or delete `src/config/site.test.ts`.
4. Verify: CI passes on a pull request.

### Step 4 — Rebuild the tokens, theme, and layout

1. Choose one token system. **DECISION NEEDED (user):** Tailwind v4 `@theme` tokens, or plain
   CSS custom properties.
2. Delete `tailwind.config.js` and the 4 copies of the theme toggle. Keep one.
3. Restore light, dark, and system modes per `docs/STYLEGUIDE.md`.
4. Fix the header (use `NAV`), the `<main>` nesting, `og:title`, and `og:url`.
5. Show a correct error message when the server returns a non-JSON error (for example a
   404 page). The form now says "Could not reach the server", which is wrong in that case.
6. Verify: the RUNBOOK smoke test passes, and axe reports no errors.

### Step 5 — Write the real content

1. Write 3 real case studies.
2. Write a real About page.
3. Move or delete `example-project.mdx`.
4. Verify: the user approves the content.

### Step 6 — Build the experience as a separate milestone

Rewrite ADR-0008 before any code. The proposed direction is below. The user decides.

- The experience is opt-in. A visitor reaches the work in one click with no gate.
- The seed comes from the browser (`crypto.getRandomValues`, time, timezone). Delete
  `api/seed.ts`. No IP address, no cookie.
- One seeded random generator drives every visual and audio value.
- The hash chain of visit events is a provenance record (a visible fingerprint of the visit),
  not a security lock.
- Use the Web Audio API and Canvas or WebGL in place of p5 and Tone.js. Load them only after
  the Enter click.
- Audio starts only after a click. The experience has a mute control, a transcript, and a
  `prefers-reduced-motion` mode.
- The visitor counter needs server state. Defer it.

### Step 7 — Clean up

1. Delete `Dockerfile`, `pi.yaml`, `vite.config.ts`, and `sonda`, or record why they stay.
2. Delete `docs/PI_CONTEXT.md` or replace it with a pointer to this plan.
3. Run the final launch checklist from the MVP plan, item 34.
